# Security reporting

Use this project's **GitHub Security → Report a vulnerability** for private
reports when that repository feature is enabled. No personal email or other
contact information is provided. Private vulnerability reporting must be enabled
when the public repository is created; a file alone does not enable it.

If the private reporting button is unavailable, open a GitHub issue asking the
maintainer to enable a private reporting channel. Include no exploit details,
credentials, private IPs, raw logs, tokens or game configuration in that issue.
Use ordinary GitHub issues for nonsecurity bugs and sanitized Job IDs/results.

This is an experimental alpha; no supported stable release or security-support
duration is promised. Keep secrets outside profiles/source/logs. Preserve narrow
AMP rights, restricted SSH forwarding, separate service identities and the local
observer boundary. The threat model and deferred qualification are documented
in README and docs/operations.md. No universal security guarantee is made.

[GitHub private reporting documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
